# 原有问答 Agent 与多轮研究 Agent 的配对开发实验

本轮比较执行器与证据交付，不比较“有无 Agent”。原 `/chat`、生产配置与旧归档保持原样。

## 冻结设计

- 原题集：v6 的 110 条 dev（官方60、仓库50），其中正例54/50。沿用原来源、版本、gold和邻接 span_coverage；不读取 test/holdout。稀疏标签不是答案正确率。
- 组件回放：全部110题比较历史 v6 上下文与新增 Agent 的一次累计打包；精确检查 v6 上下文重现，不调用回答模型。此步骤只检验新增交付环节。
- 实模 pilot：每库先按 `(SHA256(dataset:id), id)` 排序正例，再取3个不同 group_id，共6题。仅依赖ID、数据集、正例分母和组，不按失败/成功挑题；不是独立确认集。
- 三组：legacy-v6（原 AnswerService）、agent-v6-fifo（原 ResearchAgent）、agent-v6-coverage（实验子类，仅改变累计证据排序）。三组使用同一 V6ComparisonRetrieval，v6参数为 max8、无长度惩罚、保护Top1、无邻接弱先验。
- 初始原查询命中冻结 B 候选；模型自行生成的新查询使用同一原语料BGE/BM25各30、并集、同一BGE重排。所有新查询记录，不能假定三组实际查询相同。官方已有原查询英文改写仅作原配置重现；不新增翻译模型调用。
- 累计覆盖组按原问题的同一语言评分查询重排已经由工具返回的正文，复用 v6 覆盖/冗余排序，再按当前Agent引用/locator头重新核验预算。不能读取 gold、案例ID、答案或候选但未交付的正文来作选择；不得恢复已截断文字。此策略可能退化，不预定采用。
- 三组证据正文预算均为1200编码器token/4000字符；提示/JSON/来源元数据开销另计。不把两种不同提示的总输入token说成相同。
- 保留现有模型和两套提示，max_output=650、temperature=0。原链路最多2次生成，新Agent最多3次模型请求/4次工具/180秒/每工具1次重试。6题×(2+3+3)最多48次请求，共享硬上限48。无预热、失败追加重跑、模型自审或额外扩预算。模型配置调用前保存；若配置不可用，保留失败，不换模型。
- 组顺序按题号循环交错（三种排列），重复次数1。额外覆盖排序的本地重排调用、模型 usage、失败和耗时分别记录；pilot小样本与缓存影响不支持性能声明。

## 指标与采用

分别报告候选完整、累计候选完整、工具返回完整、实际最终交付完整、最终状态、协议失败、调用数、输入输出token及耗时。每题保留正文/定位/来源hash、实际模型输入与逐步产物。工具返回并集不能替代最终模型输入；未检索就结束的题按交付失败保留。

组件对照按原 group_id 做10000次簇bootstrap与配对符号置换，官方/仓库分别报告；pilot按同题列出得失，不能宣称总体显著收益。独立语义审核保持pending，不填答案正确率。采用要求新策略不损害关键条件、独立审核完成及新的确认实验；本轮不切换默认路径。
