## 预算因素

固定词面覆盖奖励为v5 C8实现，问题词仅来自原问题+冻结译文；前15原候选、非标题过滤及两种预算保持不变。交叉四个二值因素：

- 段数上限：8 / 无额外上限（仍受1200token/4000字符约束）。
- token成本指数：0.5 / 0（效用无长度惩罚）。
- 原候选保护：前1 / 前5个非标题候选。逐个按原顺序尝试完整句前缀，代码不部分截断；保护不是保住整段的保证。
- 邻接弱先验：启用 / 禁用。启用时只增加该池原T5已交付邻接段，分数为同来源同父段前15候选最高分的0.85倍；这不是BGE新评分。

每池16组+T5/T8控制，2池×18×110=3960条回放。基础配置k8/l0.5/p1/n1逐题复现v5 C8，T5/T8复现旧上下文。各组合使用相同正文、原候选、原排名；原候选指标与可选池/实际交付分别记录。计算特征可以缓存，但不能缓存不同配置的选择结果或混入标签。

主对照为基础配置分别只改变一个因素的四个对照×2池，共8个官方交付配对检验，簇bootstrap10000、seed42、簇符号置换、Holm校正。其余组合、因素边际与交互均探索性，不挑最高组合宣称单因素显著。

推进门槛官方>=44/54、仓库>=40/50、002-1与004-4完整。仅从16组合选；依次官方交付、仓库交付、较少平均交付段数、B池优先、配置名顺序。生成前冻结选择。无合格组使用B-T5作为来源隔离对照，不再重复全部旧提示生成。

## 来源风险隔离

先扫描全部冻结community片段，规则不读取问题、gold或失败ID：

1. 明确“模型总参数量=专家参数之和”的范围表述；忽略同段明确近似限定，保留六类组成相加等正常总量说明。
2. 合并访问材料中的“随机访问完全无法合并”绝对说法。
3. 合并访问/float示例中的“一次128B事务”无架构限定说法。
4. 连续地址必能以一次事务满足所有线程的无范围表述。

这些是AI来源风险标记，不能称独立人工事实确认；建议连续地址的“应该/推荐”本身不隔离。CUDA审阅对照[NVIDIA CUDA13.0.1 §10.2.1.1](https://docs.nvidia.com/cuda/archive/13.0.1/cuda-c-best-practices-guide/index.html#a-simple-access-pattern)的CC>=6.0访问例；专家层与整模的范围参照[Switch Transformer论文](https://jmlr.org/papers/v23/21-0998.html)。外部资料仅供审阅，不加入知识语料或生成提示。记录每条原文、ID、定位、原文件hash、规则和参考范围。

在冻结胜出打包策略（无胜出则B-T5）上，对110题比较Q0保留原文、Q1从全部候选、父段和邻接可选池隔离风险ID，共220条。先过滤再重新打包，禁止隔离片段通过邻接回流；原始标签不改，报告gold交集及交付损失。隔离主检验独立成对，不按结果改规则或重选打包配置。
