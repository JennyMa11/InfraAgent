# 合并检索失败原因分析

本分析重读现有 `dev-v2/rows.jsonl` 的620条检索记录、36条生成记录和当前实现；没有重新调参、运行模型、修改语料或运行test/holdout。官方指标以下均限定54道可回答dev题。完整交付指固定原始来源证据实际进入生成上下文，不等于回答正确率；稀疏gold没有穷尽中文资料中的等价证据。

邻接段落可以补齐Top5没有直接命中的证据，因此交付数可能高于Top5完整数。final的28道交付失败中，6道候选不完整，22道候选完整但Top5不完整；没有出现Top5完整而最终交付不完整的失败题。当前主要瓶颈是候选选择与排名，不是增大上下文预算。

从版本保护组到final，26道持续成功，16道成功转失败，12道持续失败，0道失败转成功。完整候选总数虽相同，不表示每道题候选集合相同。

## 1. 按库使用不同语言重排，再直接比较原始分数

`src/infra_rag/partitioned.py` 不只改变召回语言，还以各库实际查询构造重排对：官方库是英文问题＋官方正文，中文库是原始中文问题＋中文正文。随后直接按同一个reranker的原始分数排序，没有跨语言分数校准。使用同一模型并不保证这两类输入的分数具有同等含义。

54道官方题的Top5共270个位置：版本保护组中文库占66个（24.4%）；final中文库占185个（68.5%）。这证明最终选择发生显著来源偏移，但不能仅据此判定中文证据错误。

缓存额外哈希题 `official-002-1` 提供更直接证据：正确官方片段的分数在三个预处理配置中完全相同，都是0.675622344；在global30和版本保护组排第1，final排第11。final前五全部来自中文库，分数0.907—0.993，主要是匹配流程、APC介绍、自检清单和源码介绍。真正列举LoRA ID、多模态哈希和cache salt的中文片段也仅排第8。问题不仅是来源竞争，还包括主题相关内容压过直接回答所需的细节。

这是语言路由失效的明确案例；由于此次路由同时改变中文召回候选和重排问题语言，尚不能把全部退化单独归因为分数校准。需要拆开这两个变量做dev消融。

## 2. 版本保护依赖已经失效的全局排名

`prefer_versions()` 只从统一排名的前10名中挑最多2个版本匹配官方片段。正确证据若被挤到第11名之后，规则无法恢复它。final有16道题没有保护项，其中12道候选中实际存在对应产品／版本的官方片段；`missing_version_evidence` 在这些题中表示“前10内没有可保护项”，并不表示候选库没有版本证据。

缓存题的候选中有38个对应vLLM v0.10.2的官方片段，但正确片段排11，保护为空。CUDA Async题虽触发了两个版本保护项，具体解释host memory未page-locked时Async拷贝可能同步的目标片段却排54。因此“版本正确”和“能够回答问题”必须分别判断，任意保留两个同版本片段无法保证关键条件完整。

## 3. 候选名额不等于最终证据名额

分库提高完整候选覆盖46→48/54，但英文查询不变时，交付仍从预处理global30的43降到分库的40。增加候选只确保它们参与重排；统一Top5和固定预算仍允许概述挤掉精确证据。相同最大候选预算的global60交付43/54，也说明不能把分库下降简单解释为候选数量增加。分库同时改变局部BM25统计、每库候选组成与融合排序，这些因素尚未单独消融。

跨材料题 `official-004-4` 的两个官方gold在global30排2、4；版本保护组排2、10，已经无法完整交付；final进一步排22、39。最多两个产品版本保护项不能保证另一份PR证据及多条件论证齐全。

## 4. 预处理有效，但事实审计还没有形成质量过滤

预处理本身使官方完整交付40→43/54，中文仓库38→40/50；不支持“清洗导致整体失败”的判断。中文仓库MRR下降，说明覆盖改善不代表排名全面改善；它的实验也没有完整在线英文翻译路由，不能用40/50反证final在版本题上的退化。

本次预处理主要解决结构、定位、别名与可追溯性。56组近重复只审计未删除；AI材料审计是抽样提示，没有自动修改事实或将待审核段落退出检索。因此MoE专家FFN参数与完整模型总参数的范围混淆仍可能被回答复述。这个源文问题在原始和final样本中都存在，是事实质量缺口，不是此次路由新增的错误。

## 5. 保存了元数据，但没有让模型充分使用它

重排输入只有问题和正文，未显式包含官方／社区、release等元数据。生成证据提示包含引用ID、来源locator和正文，未显式告诉模型对应官方版本与可信来源级别。元数据目前主要用于可追溯和有限版本保护，尚未完整影响证据判断。

生成验证主要检查JSON、引用存在与引用ID一致性，不能验证适配器与租户盐等因果范围。已有原始组只用租户盐解释适配器隔离的样本。36条调用没有执行错误，不意味着36条事实正确；独立事实评分仍为空。final额外哈希离线样本拒答，在线样本给出不完整泛化回答，均与实际交付缺少所需具体证据一致。

## 后续优先级

1. 保留预处理global30作为实验基线，暂不采用final；先独立比较“中文仅用于召回、统一问题重排”与“不同语言重排”，固定其它设置。
2. 在对应官方版本候选内先判断问题相关性，再参与全局选择；保护应覆盖直接证据及跨来源必要条件，不能依赖全局前10，也不能强塞任意同版本内容。
3. 在最终证据选择中处理语义重复、来源覆盖和多条件完整性；重新审阅高分自检清单／概述的准入。结构清理无需推倒重来。
4. 把来源类型、版本、适用范围显式送入重排／生成提示；对已确认有范围歧义的材料人工修订或隔离，保留原文与变更记录。
5. 用同一dev题与原始证据检查新方案，并独立评审回答事实；验证通过后再决定是否切换。此次没有实施以上修复或取得新的模型成绩。
