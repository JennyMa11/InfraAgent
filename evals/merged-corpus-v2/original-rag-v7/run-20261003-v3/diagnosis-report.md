## 为什么召回增加，交付没有同步增加

1. **新证据仍被整问重排压低。** Ladj已召回CUDA条件段，但official-026-2与official-026-4的必要证据仅排第29与第17，未进入固定Top15证据选择前沿。同一事实在official-026-3排第4并成功交付，说明问法与条件匹配仍是瓶颈。
2. **补入的新候选挤占旧证据的排名和预算。** official-010-3必要证据从第8降到第15，official-030-4从第7降到第11，原始重排分数不变，仍在候选甚至前沿中，但最终不再交付。Ladj恢复005-2、026-3，同时丢010-3、030-4，官方净增为0。本轮没有改变重排语言，不把这种竞争归因于不同语言原始分数偏差。
3. **进入前沿仍不保证正文交付。** repo-075-2的必要段在Ladj排第6、分数0.587且进入选择前沿，最终正文仍不完整。official-012-4与repo-045-2在T中也继续表现为候选完整、交付失败。固定预算和保护首段下的实际选择仍需改进，不能用命中ID代替完整正文。
4. **扩大入口与拆问题都有退化。** D90仓库交付净增1题，却在官方丢2题；Q官方交付从45降至42。组合T+Ladj与单独Ladj的完整指标相同；相邻段整问重排和前沿扩展也未带来稳定净增。不能把各方法各自恢复的题目相加当作一个可采用配置。

下一轮优先验证：在固定候选下，对问题条件进行覆盖感知的整问重排/证据选择，并独立控制Top15前沿及保护首段。暂不继续盲目扩大入口，不重新引入新增研究Agent；新实验须另冻结协议和预算，不能使用gold驱动线上选择。
