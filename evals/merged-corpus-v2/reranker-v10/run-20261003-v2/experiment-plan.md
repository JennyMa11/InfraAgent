# E4：固定候选换重排器（v10，开发集）

v9文档内定位使官方完整候选增加4题，但交付未通过门槛。本轮只更换重排器，检查前沿排序与最终预算选择。保留旧gold和分块，不读test/holdout；独立人工审核pending，不改变默认配置，不生成答案。

## 冻结对照

候选仅为v9的B与Doc固定池；每题候选ID及原融合分、scoring_query、原正文/来源、定位不变。原bge-reranker-base和BAAI/bge-reranker-v2-m3分别评分，在每池使用O15/X30固定打包，共2池×2模型×2方法×110题=880条。base组逐字复用v9的440条经机械审核的上下文；m3组对同一原文重新评分。不能按gold调整输入、范围、权重或分数。

m3 revision固定为 `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`，官方API列567755777个F32参数；下载后冻结6个配置/分词/权重文件SHA256。不执行remote code。base沿用旧revision及hash；软件版本沿用锁文件并记录实际torch/transformers/sentence-transformers版本。

两重排器保持原文输入，pair最大长度512、默认longest-first截断，float32、MPS（若本机MPS不可用则本轮不启动，另立CPU协议）。明确以sigmoid(logit)归一化，非负分满足旧打包器接口；该分数不是经校准的证据充分概率。质量组件中m3仅复用本轮完全相同的模型、查询、正文hash评分；不把base分数作为m3缓存。记录原始logit、归一化分数、token输入长度、截断、所有首次推理及耗时。设备、精度、分词器变化属于模型控制的实际属性，披露可见输入差异，不能声称token级输入完全相同。

正文仍用旧bge-small-zh-v1.5计数器，1200 token、4000字符、最多8段；Top1保护、前沿、目标权重、交换次数及proposal上限不改。候选≤90，每配置实际评分对≤90；来源头序列化开销另列。现有16GB内存与约727GiB空余磁盘不证明速度可接受。

## 统计与开发筛选

官方60题（54正例、6负例）、仓库50正例。每库每池每方法的m3对base为主要比较家族，共8项；簇bootstrap10000次、seed42、簇符号置换、Holm校正，报告恢复/丢失和覆盖。另报Top5/15/30完整排名，必要证据项排名及原评分口径MRR/nDCG，稀疏judgments风险不变。

候选数固定，不把候选完整率变化当模型收益。开发筛选仍要求两库完整交付均不低于原B-O15，合计净增至少2；同时检查同池/同方法base对照，区分旧Doc或交换收益。多个m3配置通过时按合计交付、官方交付、仓库交付降序、配置ID升序选一个。无配置通过则停止性能/embedding扩展，回到标签充分性与选择失败诊断，不另扫模型或输入长度。

只有通过质量筛选才进入真实暖性能：同110题交错运行原B-O15与选定候选各一次，关闭查询/重排结果缓存；Doc scope由本次base重排确定，base候选筛选开销及新模型全部评分均计入实际累计90对。若Doc先重排B再以m3对全部候选评分超过90，则该配置明确预算失败，不能隐藏base评分或借旧scope冒充在线结果。可运行的B-m3对照无需额外base重排，直接实际B召回后m3评分。模型/索引预热，冷加载与内存开销单列，p95 nearest-rank≤同期B的1.5倍；实际交付重新审计。

质量不等于最终采用。独立来源/答案/引用审核与确认评测未完成时adoption为false；回答正确率、citation precision、hallucination rate为null。保存hash与全量机械产物，不覆盖v7/v8/v9。
