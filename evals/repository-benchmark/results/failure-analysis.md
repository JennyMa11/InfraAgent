# 三仓库实验结果偏低的原因分析

本次分析复用固定语料、问题与标注，读取全部逐题结果，并补做两路Top30、RRF候选及精确向量检索诊断。没有修改检索参数、原始标签或基线分数；不是新的调参实验。

## 1. 评价标签不完整，部分失败属于指定证据定位失败

测试集重排Top5有23题未命中指定证据。内容核查发现其中12题存在可能等价的未标注证据，记录在 `equivalent-evidence-review.json`。这是AI初步审核，尚需独立人工确认，不据此发布修正后的指标。

例如 `repo-001-1` 问Warp的定义与线程数，第一名已经明确回答最小调度单位和32个连续线程，却不是题集指定的源分块；`repo-024-2` 第一名明确说明用Nsight Compute分析Kernel；`repo-033-2` 第二名解释c_KV上投影还原K/V。这些均被原chunk-ID标签计作未命中。

三个仓库包含大量同主题内容，每题通常只标一处原文。固定证据的Recall不能直接当作“是否检索到正确知识”的概率。跨来源等价内容需要补标，但必须保留原始版本与成绩。

## 2. 等权RRF偏好两路共同结果，融合后截断又丢失证据

测试集由BM25转为混合检索：原先命中的9题丢失，仅新增2题，净少命中7题。重排可追回部分排序错误，但不能取回候选阶段已丢弃的分块。

当前每路取30个候选，使用等权RRF，常数60，再把融合结果截成30。单路第一名得分为1/61≈0.0164；两路均排第30的结果得分为2/90≈0.0222。因此在这组候选范围内，两路都出现的结果必然压过只在一路出现的结果，哪怕后者是BM25第一名。共同匹配主题却缺少精确事实的分块可能因此靠前。

| 测试集阶段 | 至少含一个指定证据的题数 |
|---|---:|
| BM25 Top30 | 85/100 |
| BGE Top30 | 75/100 |
| 两路候选并集，最多60个 | 91/100 |
| RRF后保留30个 | 86/100 |
| 重排后Top5 | 77/100 |

23道未命中题按固定标签分解为：9题证据未进两路候选、5题进了并集但被融合截断、9题进入重排候选但未进入Top5。这个分解针对指定标签，不代表其中23题全部回答错误。

## 3. 分块后语义上下文不足，标题输入也不一致

11,168个块的长度中位数仅120字符；4,022个块不足80字符（36.0%），2,045个不足40字符，404个仅为分隔线。规范化正文完全相同的额外分块有562个；这是分块重复统计，并非近重复语义检测。

短块并非都无效，但独立标题、分隔线、破碎代码和缺乏上文的句子会带来检索噪声及候选重复。三级分块流程存在，并不证明分块质量已经达到预期。

BM25使用正文加最近标题；BGE编码与reranker只使用正文。有些块保留Markdown标题，有些没有。测试集51个唯一标注块中，35个最近标题未出现在正文。标题本身还可能缺失祖先小节主题。

具体例子：`repo-004-1` 的正确块只写“Block内所有线程到达此屏障……”，正文没有`__syncthreads`，最近标题只是“2.1 基本语义”。问`__syncthreads`时，两路Top30都未召回它，前排反而是Memory Fence等邻近概念。需要保存文件主题和标题层级，再统一提供检索/重排文本。

此外，当前标题启发式可能把编号列表或数字开头的公式识别为标题。此次结果出现“2. **内存可见性**”和数学表达式作为heading，应在后续分块修复中处理。

## 4. 场景题的概念映射和精确排序不足

| 测试集方法 | 知识题Recall@5 | 场景题Recall@5 |
|---|---:|---:|
| BM25 | 81% | 62% |
| BGE | 65% | 40% |
| 混合 | 75% | 54% |
| 混合＋重排 | 91% | 62% |

重排后差距仍为29个百分点。场景问法往往不直接出现原文术语，例如“P节点/D节点”需要关联Prefill/Decode与KV交接，“首字提前但出词速度不变”需要关联TTFT与token间隔。

这支持当前表示、术语映射和问题细节匹配仍需改进的判断，但不能单独证明BGE模型容量不足：漏标、上下文缺失和融合截断同时存在。模型升级效果需要控制其他变量后验证。

## 5. 近似向量索引不是当前主要损失来源

用现有向量做精确cosine Top30对照：测试集指定证据命中数为76，Chroma为75；精确与近似Top5的命中题数均为53。两个划分全部150题的混合Top10均复现原基线。

因此本次诊断没有证据表明大幅损失来自向量库近似搜索。暂不优先调整数据库索引参数。

## 6. 指标口径和原先预期不一致

早期60题仅在6篇AI自编短笔记上评测；本次是在87篇真实正文与11,168个分块上寻找指定证据，题目及标注也不同。两者的高低不能当作同一测试集上的性能下降。

本次每题通常只有一个标注块。即使唯一正确块进入Top5，Precision@5也只有1/5=20%，F1为1/3；因此15.4%的Precision不能直接解释为其余84.6%的内容错误。多证据题的上限与此不同。

服务返回父块扩展context，但评估只检查命中子块ID。23道未命中题中，有2道Top5包含同一父块的兄弟块，说明子块定位分数与扩展上下文的可用性不同。现有诊断未单独检查4,000字符上下文是否最终包含完整证据，不能直接把这2题改判为成功。

## 优先处理顺序

1. 人工复核可能等价证据，版本化补全标注，保留原始指标。
2. 在dev上移除分隔线/无信息块，保留标题层级，统一BM25、向量与重排输入上下文。
3. 在dev上比较BM25＋重排、保留完整候选并集的混合＋重排，以及不同候选数量；不要依据test诊断直接选参数。
4. 在dev上验证Infra术语别名与场景查询改写，之后再控制变量比较模型或分块策略。
5. 同时报证据命中率、Recall、MRR、延迟及上下文证据覆盖；不要把检索指标称作生成问答准确率。

重排新增约540ms的P50耗时（混合60.8ms、重排600.4ms）；当前最多30对查询/正文交叉编码是明确的新增计算。若保留完整并集，需同步测延迟。没有单独的设备或算子Profiling，暂不把耗时归因于特定CPU/GPU执行方式。

- `equivalent-evidence-review.json`：12条可能等价内容的初步审核，待独立人工复核。
- `comparison.md`：未修改的原始基线。
